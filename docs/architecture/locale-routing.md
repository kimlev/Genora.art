# Языковые адреса сайта

## Схема адресов

У каждого языка постоянный адрес с префиксом: `/ru/`, `/en/`, `/es/` и так далее для всех языков из `localeOptions` (`prototype/src/lib/i18n/index.ts`).

Один и тот же префиксный адрес всегда отдаёт один язык и не зависит от настроек браузера. Поэтому ссылку можно отправить другому человеку и он увидит тот же язык.

Без префикса живут только служебные разделы: `/api/...`, `/admin/...`, `/blogoro/...`.

## Как устроены маршруты

Все страницы сайта лежат в сегменте `prototype/src/app/[locale]/...`, то есть язык — настоящая часть маршрута, а не подмена адреса. Неизвестный язык в первом сегменте даёт 404 (`prototype/src/app/[locale]/layout.tsx`).

Вне сегмента остаются только служебные маршруты: `app/api/**`, `app/admin/**`, `app/blogoro/**`, `robots.ts`, `sitemap.ts` и корневой `layout.tsx`, который задаёт `lang` и `dir` документа.

## Как определяется язык

`prototype/src/proxy.ts` обрабатывает каждый запрос страницы:

1. Адрес с префиксом (`/en/pricing`) — запрос проходит без подмены пути, язык передаётся серверным компонентам заголовком `x-genora-locale` и сохраняется в cookie `genora-locale`. Явный `?lang=` перекрывает префикс и уводит редиректом на постоянный адрес запрошенного языка.
2. Адрес без префикса (`/pricing`, `/`) — временный редирект `307` на префиксный адрес. Язык выбирается по порядку: параметр `?lang=` (обратная совместимость со старыми ссылками) → cookie с выбором пользователя → `Accept-Language` браузера → русский.

Ответ с редиректом помечен `Vary: accept-language, cookie`, чтобы промежуточные кеши не отдавали чужой язык.

Выбор пользователя приоритетнее автоопределения: после переключения языка в интерфейсе адрес меняется на новый префикс, выбор пишется в cookie, `localStorage` и профиль пользователя.

## Клиентская часть

- `LocaleProvider` берёт язык из префикса адреса; при переключении языка выполняется переход на адрес нового языка, поэтому серверная часть страницы тоже приходит переведённой.
- Ссылки внутри сайта ставятся через `Link` из `@/components/ui/locale-link` — он сам добавляет префикс, поэтому переходы не идут через редирект. Переходы кодом — через `useLocalePush()` и `useLocaleRouter()` (`prototype/src/lib/i18n/use-locale-push.ts`).
- Компоненты не сравнивают `usePathname()` напрямую: для маршрутов используется `useAppPathname()` (`prototype/src/lib/i18n/use-app-pathname.ts`), который отбрасывает языковой префикс.
- Помощники разбора адресов: `splitLocalePath`, `withLocalePath`, `localizeHref`, `isUnlocalizedPath` (`prototype/src/lib/i18n/locale-path.ts`), тесты — `prototype/tests/locale-path.test.mjs`.

## SEO

- `canonical` каждой страницы указывает на префиксный адрес текущего языка.
- `hreflang` перечисляет все языки плюс `x-default`.
- `sitemap.xml` содержит отдельную запись для каждого языка каждой публичной страницы.
- Статья блога канонизируется на адрес своего языка: контент приходит от внешнего сервиса на языке оригинала, а интерфейс страницы переводится.
- `robots.txt` закрывает приватные разделы во всех языках (`/login`, `/*/login` и так далее).

## Письма

Ссылки в письмах подтверждения и восстановления пароля собираются сразу с префиксом языка письма, чтобы получатель не проходил через редирект.
