# Поисковые системы: индексация и статистика

## Что уже подтверждено

- **Google Search Console** — ресурс `sc-domain:genora.art`, право подтверждено TXT-записью в DNS Namecheap (`@ → google-site-verification=…`). Удаление записи снимает подтверждение.
- **Яндекс Вебмастер** — право подтверждено файлом `prototype/public/yandex_a11d3c68d4c7fd33.html`. Файл лежит в репозитории и раздаётся с корня сайта; удалять его нельзя.
- Карта сайта `https://genora.art/sitemap.xml` отправлена в Google, в Вебмастере добавляется вручную в разделе «Индексирование → Файлы Sitemap».

## Как страницы попадают в индекс

Правило разделения по языку живёт в `prototype/src/lib/search-routing.ts`:

- **любая страница, включая русскую, → Google**: повторная отправка карты сайта, после которой Google перечитывает её и находит новый адрес вместе с языковыми альтернативами;
- **дополнительно русская страница → Яндекс**: IndexNow плюс постановка адреса в очередь на переобход через API Вебмастера. Другие языки в Яндекс не отправляются: он их не продвигает.

Отправкой управляет `prototype/src/lib/server/search-submit.ts`, вызов происходит при публикации статьи из Blogoro (`prototype/src/app/blogoro/publish/route.ts`). Ошибка любого канала не ломает публикацию: она попадает в журнал вместе с адресом и языком.

Почему у Google другой канал: своего приёмника адресов для обычных страниц у него нет. Indexing API работает только для вакансий и прямых трансляций, а ручная кнопка «Запросить индексирование» в интерфейсе ограничена примерно десятком адресов в сутки. Поэтому для не-русских языков карта сайта — единственный автоматический путь.

Ключ IndexNow раздаётся по адресу `https://genora.art/indexnow-key.txt` (`prototype/src/app/indexnow-key.txt/route.ts`). Без переменной `INDEXNOW_KEY` адрес отвечает 404, а уведомления просто не отправляются.

Адрес статьи собирается сразу с языковым префиксом (`/en/blog/slug`), чтобы поисковик получал страницу, а не редирект.

## Карта сайта

`prototype/src/app/sitemap.ts` собирается на каждый запрос (`dynamic = "force-dynamic"`). Раньше файл создавался при сборке образа, когда база недоступна, и в поисковики уходил список демонстрационных статей: их страницы отвечают 404, как только в базе появляется хотя бы одна настоящая статья. Демонстрационные статьи помечены `source: "static"` и в карту сайта не попадают.

## Где хранятся доступы

Основное место — таблица `search_credentials` (миграция `024_search_credentials.sql`), чтение и запись — `prototype/src/lib/server/search-credentials.ts` с кешем на минуту. Так значения переживают пересборку контейнера, а токен Яндекса приложение обновляет само: за неделю до истечения оно меняет его по `yandex_refresh_token` и сохраняет новый в ту же таблицу.

| Запись | Назначение |
|---|---|
| `yandex_access_token` | Текущий OAuth-токен Вебмастера |
| `yandex_refresh_token` | Обмен на новый токен без участия человека |
| `yandex_expires_at` | Момент истечения в миллисекундах |
| `yandex_client_id`, `yandex_client_secret` | Приложение на `oauth.yandex.ru`, от имени которого идёт обновление |
| `yandex_host_id` | ID сайта в Вебмастере, например `https:genora.art:443` |
| `google_client_email`, `google_private_key` | Сервисный аккаунт Search Console |
| `google_site` | Ресурс в Search Console, по умолчанию `sc-domain:genora.art` |

Записать значения на сервере (JSON с теми же именами полей):

```
docker exec -i genora-app node scripts/save-search-credentials.mjs < creds.json
```

Переменные окружения остались запасным вариантом для локальной разработки: `YANDEX_WEBMASTER_TOKEN`, `YANDEX_WEBMASTER_HOST_ID`, `GOOGLE_SEARCH_CONSOLE_CLIENT_EMAIL`, `GOOGLE_SEARCH_CONSOLE_PRIVATE_KEY`, `GOOGLE_SEARCH_CONSOLE_SITE`. Отдельно от базы живёт только `INDEXNOW_KEY` — ключ раздаётся статическим файлом.

Все доступы необязательные. Если их нет, раздел «Поиск и индексация» в админке показывает инструкцию, а сайт работает как обычно.

## Как получить доступы

**Google.** В Google Cloud создать проект, включить в нём Search Console API, создать сервисный аккаунт и JSON-ключ. Затем в Search Console открыть «Настройки → Пользователи и разрешения» и добавить почту сервисного аккаунта с правом чтения. Из JSON-файла в переменные попадают `client_email` и `private_key`.

**Яндекс.** На `oauth.yandex.ru` создать приложение с правом доступа к Яндекс Вебмастеру, получить код подтверждения от имени владельца сайта и обменять его на пару токенов. Дальше обновление идёт само, пока в базе лежат `yandex_refresh_token`, `yandex_client_id` и `yandex_client_secret`.

## Что показывает админка

Раздел «Поиск и индексация» (`prototype/src/components/admin/admin-seo.tsx`, данные — `/api/admin/seo`):

- Google: клики, показы, CTR, средняя позиция, топ запросов и страниц за период. Данные приходят с задержкой два-три дня — это поведение Google.
- Яндекс: ИКС, страницы в поиске и исключённые, показы и клики за период, топ запросов, счётчики проблем сайта.
- Ручная отправка адресов в IndexNow.

Ответы обеих систем кешируются в памяти процесса на десять минут, кнопка «Обновить» запрашивает их заново. Раздел админки не переводится и остаётся на русском по правилу `genora-i18n-coverage`.
