# Карта: куда попадает новый провайдер и новая модель

Когда в Genora.art появляется новый AI-провайдер или модель, они должны сразу быть видны в фильтрах, каталогах и рейтингах. Этот файл — чеклист. Сначала источник правды, потом места, которые ещё заданы вручную.

## Источник правды

Живой список берётся из IntegratorAI и пишется в таблицы `ai_providers` и `ai_models` функцией `syncIntegratorCatalog` (`prototype/src/lib/server/catalog-sync.ts`).

После синка **сами подтягиваются** (менять код не нужно, если запись есть в БД / Integrator):

| Поверхность | Где |
|---|---|
| Чат: выбор провайдера и модели | `provider-picker.tsx`, каталог из `/api/catalog` |
| Тариф | `pricing-page-content.tsx` |
| Рейтинг / мой рейтинг | `rating-page-content.tsx` |
| Каталог моделей | `models-catalog-page.tsx` + `getCatalogData` |
| Админка → Модели | `admin-models-data.ts` (Integrator + картинки) |
| Админка → Множитель цены | `/api/admin/pricing-multipliers` |
| Админка → Использование: фильтры провайдера и модели | `getAdminDashboardData` / `getAdminUsageSlice` читают `ai_providers` и `ai_models` |
| Лендинг: бегущая строка провайдеров | `marquee-section.tsx` |

На dest список шире, чем на проде: на проде в Integrator ещё нет части провайдеров, поэтому в фильтрах прода их не будет, пока их не отдаст Integrator и не пройдёт синк.

## Что править вручную при новом провайдере

Без этих правок логотип, подпись или запасной список могут остаться старыми.

1. **Логотип**
   - файл `prototype/public/providers/<id>.svg`
   - запись в `prototype/src/components/chat/provider-logo.tsx`
2. **Человеческое имя**
   - `PROVIDER_NAMES` в `prototype/src/lib/server/catalog-sync.ts`
   - `PROVIDER_NAMES` в `prototype/src/lib/admin-models.ts`
3. **Сопоставление id ↔ название** (чат, битва, биллинг)
   - `PROVIDER_IDS` в `prototype/src/lib/provider-id.ts`
   - запасная карта в `chat-shell.tsx` (`providerSelectionFor`)
   - запасная карта в `battle-shell.tsx`
4. **Картинки / тип модели**
   - если это image-провайдер: `IMAGE_PROVIDER_NAMES` в `prototype/src/lib/catalog/model-kind.ts`
5. **Запасной прайс**, если Integrator недоступен
   - модели в `prototype/src/lib/catalog/commercial-models.ts`
6. **Маркетинговый текст** (не фильтр, но список провайдеров в FAQ/описании)
   - локали в `prototype/src/lib/i18n/locales/*.ts`

Платёжные провайдеры (StreamPay и т.д.) — другой контур. Их эта карта не касается.

## Что править вручную при новой модели

1. Дождаться, пока Integrator отдаст модель, и чтобы прошёл `syncIntegratorCatalog`.
2. Если модели ещё нет у Integrator, но она должна быть на сайте — добавить строку в `commercial-models.ts`.
3. Проверить админку → Использование: модель должна появиться в списке «Модель» без того, чтобы по ней уже были запросы.
4. Рейтинг, тариф и чат читают каталог — отдельный список моделей туда не копировать.

## Админка → Использование

- Фильтры: период, пользователь, **все** провайдеры каталога, **все** модели каталога.
- Таблица: первые 25 строк, следующие пачки подгружаются при прокрутке вниз.
- Карточки «Запросы / Вход / Выход / Себестоимость / Доход / Прибыль» считаются SQL-итогами **по всей выборке**, а не по видимым строкам.
- Догрузка идёт через `/api/admin/usage`, без полной перезагрузки дашборда.

## Как проверить, что ничего не забыли

1. В чате новый провайдер есть в выпадающем списке и у него логотип.
2. В тарифе и рейтинге он фильтруется.
3. В админке → Использование он есть в «Провайдер», его модели — в «Модель».
4. В админке → Модели и «Множитель цены» он есть в списке.
